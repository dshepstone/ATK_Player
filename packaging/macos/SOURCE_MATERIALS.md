# Dependency notices and corresponding source (macOS)

This macOS distribution includes the source and license materials locally in
`ATKPlayer.app/Contents/Resources/licenses/dependencies` (Control-click the app,
choose Show Package Contents). No purchase, account, or source-request email is
needed. `SHA256SUMS.txt` identifies the files; `DEPENDENCY-SOURCE-LOCK.json`
records upstream URLs, versions, revisions and archive digests. Sources are not
application plugins and their inclusion does not enable any additional codec or
Qt module.

These are the same materials, generated by the same script
(`packaging/windows/prepare-dependency-materials.py --platform macos`), as the
Windows distribution ships, except WiX, which is part of the Windows installer
only.

## Qt 6.9.3

`sources/qtbase-6.9.3-source.zip`, `qtmultimedia-6.9.3.tar.xz` and
`qtsvg-6.9.3.tar.xz` contain the unmodified upstream source code, including
embedded third-party code and build scripts. Their `.tag` files identify the
revisions. The installed kit's SPDX inventories and `config_qt*.opt` /
`.summary` files accompany them. The notices keep the upstream attribution
records, linked license and copyright files, and source copyright/license
comment blocks; this is a superset that also describes build tools, tests and
unselected implementations.

ATK Player uses the LGPL v3 option for its Qt frameworks; LGPL v3 and the GPL v3
text it incorporates are supplied. Third-party code keeps its own terms. A GPL
alternative in the reference corpus does not mean a GPL-only implementation is
in the application.

The Qt frameworks and plugins are separate, replaceable files in
`Contents/Frameworks` and `Contents/PlugIns`. To use a modified Qt, build it
from these sources with Qt's macOS (Xcode command line tools, CMake, Ninja)
instructions and the supplied configuration, for the same architecture, and
replace the matching frameworks and plugins. Then re-sign the app, because
macOS refuses to run code whose signature no longer matches:

```bash
codesign --force --deep --sign - ATKPlayer.app
```

That re-signs ad hoc (or use your own identity). Alternatively rebuild and
relink ATK Player itself from the included MIT source against your Qt; see
`docs/BUILDING.md`, "Building on macOS".

## FFmpeg 9.0.1, vcpkg port revision 1

`sources/FFmpeg-9.0.1-patched-source.zip` contains upstream `n9.0.1` with the
patches from the pinned vcpkg port applied in port order.
`sources/FFmpeg-vcpkg-port.zip` preserves that port and all its patches, and
`sources/vcpkg-build-source.zip` the pinned build system and helper ports.
`FFmpeg-BUILD-CONFIGURATION.json` records the five distributed dylibs' hashes,
configuration strings and LGPL license results. Absolute paths in configure
strings describe the original build environment.

To rebuild: clone Microsoft's public vcpkg at the baseline in
`DEPENDENCY-SOURCE-LOCK.json`, then build ATK Player with its `macos-arm64-*` or
`macos-x64-*` CMake preset. Those use the `arm64-osx-atk` / `x64-osx-atk`
overlay triplets in `cmake/triplets` (dynamic libraries, macOS 12 minimum).
The default features stay disabled, and no GPL, nonfree, x264, x265 or fdk-aac
feature may be selected for this distribution. Replace the five matching
`libav*` / `libsw*` dylibs in `Contents/Frameworks` (keeping their `@rpath`
install names), then re-sign the app as above.

## Source-only archive exclusions

The qtbase and vcpkg archives are source-only repacks of checksum-verified
upstream archives. `SOURCE-EXCLUSIONS.json` lists every omitted member:
prebuilt binaries, unused font fixtures and test signing material. No deployed
runtime file or C/C++ build source is removed or modified.

## ATK Player

`sources/ATK-Player-source.zip` snapshots the tracked source used by the
packaging build, under the project's MIT License. The project and its history
are public at https://github.com/dshepstone/ATK_Player.
